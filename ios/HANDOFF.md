## 2. 꼭 알아야 할 함정

- **조각 모드.** 기기 어디선가 짧은 입출력 주기를 쓰는 앱이 돌면 `audioApp` 버퍼 모양이 통째로 바뀐다
  (초당 수백 개, 대부분 0, 진짜 소리는 버퍼마다 한 조각, pts 무의미). 처음 증상이 "무음 · 8배속"이었던 이유다.
  사파리 Web Audio 페이지 하나만 열어도 재현된다.
- **확장은 Debug 에서도 `-O`.** 빼면 처리가 늦어져 ReplayKit 이 버퍼를 버리고, 그게 또 다른 버그처럼 보인다.
- **화면 잠금 = 방송 종료.** 테스트 중 자동 잠금이 걸리면 테스트가 멈춘 것처럼 보인다.
  앱은 공유 중 자동 잠금을 끈다.
- **`test-without-building` 은 앱을 다시 깔지 않는다.** 코드를 바꿨으면 `devicectl device install app` 으로 직접 깐다.
- **사파리 탭이 남아 계속 소리를 낸다.** 측정 전에 사파리를 끄고 시작한다.

## 3. 판정은 숫자로

귀로 판단하지 않는다. Debug 빌드에서 `curl http://<아이폰IP>:7980/diag` 로 초당 출력량(`outSecPerSec`),
`sparse`, `underruns` 를 본다. 측정은 1kHz 순음을 재생해 받은 WAV 의 속도(기본 주파수 비)와 SNR 로 했다.
`/diag` 는 방 비밀번호(`pw`)도 내주므로 **Debug 전용**이다.

## 4. 남은 일

- 실제 음악 앱으로 10분 이상 공유하며 `/diag` 와 청취자 쪽 언더런 확인
- ReplayKit 이 버퍼를 1/4 만 준 경우(한 번 관찰, 재현 안 됨) — 다시 보이면 `/diag?rec=1` 로 원본을 떠 둔다
- 카메라로 초대 QR 을 찍어 앱이 열리는지 확인
- 출시 전: 심사 정책 확인(타 앱 소리를 네트워크로 내보냄)

## 5. 작업 규칙

- **커밋은 메시지를 먼저 보여주고 허락받은 뒤에만, 푸시는 요청받을 때만** 한다
- 커밋 메시지에 `Co-Authored-By` 를 넣지 않는다
- 에러 로그만 받으면 바로 고치지 말고 **원인 분석 + 수정 계획을 먼저 보고**한다
- 추측으로 "됐다"고 말하지 않는다. **실제로 잡힌 값을 확인하고 말하라.**
